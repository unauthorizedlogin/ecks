# 📊 Event Viewer Data

## Overview

The Event Viewer Data layer defines the **data structures used by the Event Viewer system**.

It separates event information, channel definitions, tab/view configuration, filtering, and presentation settings from the UI and `EventManager`.

The layer currently consists of four data types:

* `EventViewerMessage` — individual runtime events.
* `EventViewerChannel` — channel definitions and channel configuration.
* `EventViewerTab` — predefined channel groupings.
* `EventViewerView` — configurable view/filter state.

---

# Architecture Role

```text
Event Sources
     │
     ▼
EventViewerMessage
     │
     ▼
EventManager
     │
     ├── Channels
     ├── Views
     └── Buffers
     │
     ▼
EventViewerUI
```

The data classes provide the structures that the manager and UI operate on.

---

# EventViewerMessage

`EventViewerMessage` represents **one event generated by the game**.

```text
EventViewerMessage
├── channel
├── severity
├── source
├── message
├── timestamp
└── data
```

### Severity

The message supports five severity levels:

```text
INFO
SUCCESS
WARN
ERROR
DEBUG
```

### Runtime Data

Each message records:

* `channel` — event category.
* `severity` — importance level.
* `source` — system that generated the event.
* `message` — human-readable event text.
* `timestamp` — creation time in milliseconds.
* `data` — optional structured information for future systems.

The `data` dictionary allows events to carry machine-readable information such as:

```text
item_id
quest_id
entity_id
damage_type
```

without forcing that information into the displayed message.

---

# EventViewerChannel

`EventViewerChannel` defines **what a channel is and how it behaves**.

```text
EventViewerChannel
├── id
├── display_name
├── color
├── show_in_ui
├── enabled
├── export_enabled
├── min_severity
└── group
```

### UI Controls

```text
color
show_in_ui
enabled
```

These control whether and how the channel appears in the Event Viewer.

### Export Control

```text
export_enabled
```

Controls whether events from the channel are eligible for exported/build logging.

This separates **runtime logging** from **UI visibility**.

### Severity Filtering

```text
min_severity
```

Provides a channel-level minimum severity threshold.

### Grouping

```text
group
```

Allows channels to be grouped into broader categories or tabs.

---

# EventViewerTab

`EventViewerTab` defines a **static grouping of channels for a tab**.

```text
EventViewerTab
├── id
├── display_name
├── allowed_channels
└── show_all
```

`allowed_channels` specifies which channels belong to the tab.

When:

```text
show_all == true
```

the tab represents all available channels.

This provides a simple predefined grouping layer above individual channels.

---

# EventViewerView

`EventViewerView` represents a **configurable event-log view**.

Unlike `EventViewerTab`, which primarily defines channel membership, a View provides additional filtering and presentation configuration.

```text
EventViewerView
├── id
├── display_name
├── include_channels
├── exclude_channels
├── min_severity
├── keyword_filters
├── group_repeats
└── channel_colors
```

### Channel Filtering

```text
include_channels
exclude_channels
```

Allows a view to explicitly include or exclude channels.

### Severity Filtering

```text
min_severity
```

Sets the minimum severity accepted by the view.

### Keyword Filtering

```text
keyword_filters
```

Provides support for filtering events based on message content.

### Repeat Grouping

```text
group_repeats
```

Provides a future presentation option for collapsing repeated events.

### Channel Colors

```text
channel_colors
```

Allows a view to maintain channel-specific color overrides.

# Architectural Distinction

The four structures serve different purposes:

| Type                 | Purpose                                      |
| -------------------- | -------------------------------------------- |
| `EventViewerMessage` | Runtime event instance                       |
| `EventViewerChannel` | Definition/configuration of an event channel |
| `EventViewerTab`     | Predefined grouping of channels              |
| `EventViewerView`    | Configurable filtered presentation of events |

The important separation is:

```text
MESSAGE
What happened?

CHANNEL
What category does it belong to?

TAB
Which channels does this predefined view contain?

VIEW
How should those events be filtered and presented?
```

This gives the Event Viewer a data model that can support the current UI while leaving room for more advanced filtering, grouping, export, and presentation features later.
